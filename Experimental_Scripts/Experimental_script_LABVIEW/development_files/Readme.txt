Experimental script for the Cardio Audio Synch (CAS) task

Main script : ActiView903-RealTime_CAS.vi
Based on the Actiview903 version of Dr.Coen Metting van Rijn, CEO of the Biosemi compagny. 
Software version : LABVIEW 2022 Q3 (64-bit) 22.3.1f8

FILES
- 'ActiView903-RealTime_CAS.vi' : the main VI script to open
- 'Compilation_instruction.pdf' : description how to setup the project and compile
- all other files : sub-VI needed to the functionning the the main VI. 
Note: VI = Virtual Instrument = file in LabView.

USE OF THE SCRIPT
The experimental script is based on ActiView software which is the dedicated tool associate with the Biosemi ActiveTwo system used to record EEG, ECG and Respiration data. 
The source code have been provided by Dr.Coen. 
INPUT: - At the software initiation, the user has to specify the path where to find the 'logfile_*.txt' and 'CardioSynchExperimental_*.txt' for the current participant generated by the processing MATLAB script 'ECG_R_peak_detection_Compute_Variance_LABVIEW_version_V2.mat'
- The user has to stop and start a new recording for each experimental bloc. 
- He has to specify which are the current bloc (1-4) 
- He has to specify if the following condition is Synch (sound synchronized with the heartbeat) or Asynch (sound not synchronized with the heartbeat)
- Change the toggle button "Task OFF/ON" to start experiment (button disable at the end of a bloc until stop and restart a file)
- In case of bad detection of R-peak (visual check), the user can adjust the threshold with the element "R-peak Threshold adjust". Using 0-1 value du decrease it (more sensitive), using >1 to increase the threshold (more conservative). 

These manipulation are independant of other standard manipulation in ActiView (start file, unpaused the recording, .....) 

DETAILS DESCRIPTION OF SCRIPT FUNCTIONNING 
There is three level to consider in the BlockDiagramView
1. Level 1: initialisation outside of the main loop (background white outside) which are execute only once at the start of the program. 
You can found here: 
- loading to the 'logfile_*.txt' and extract of the threshold value
- loading to the 'CardioSynchExperimental_*.txt' and extract othe matrix of experimentation (size 300x6)
- Initialisation of the ECG vector which will contain the 102 previous value of EXG1-EXG2 (ecg1) which correspond to a 50ms with the default sampling rate of 2048Hz
- Initialisation of the sound/tone used during the experiment. It is a sin wave of 1000Hz sampled at 44.1 kHz of 1s with a ramp-up and ramp-down of 70ms
- Initialisation of the communication port to send trigger (using VISA serial) to the Biosemi system.

2. Level 2: the buffer loop (green rectangle inside). This part is execute each time than the buffer of Actiview received new data from the USB receiver box. The variable between each loop is variable due to the 
nature of the USB port (never realtime but package). However, no data are missing because all data arrived in packages. The average time is around 8ms but increase to 70ms after a sound play (but I repeat: no data lost because stock in the buffer in the meanwhile).
The following elements take place here: 
- The data from EXG1 and EXG2 are extracted from the buffer to be substracted and convert into uV. 
- Execution of the subVI 'Generate ECG vecor' which fill the ECG vector with the last upcoming data (when arrived to the end, restart at the beginning of the vecor)
- Execution of the subVI 'R-peak dector', which detect the R-peak when the variance of the signal inside of ECG vector (previous 50ms) reatch the threshold ((https://doi.org/10.1038/s41598-017-13861-8). In addition, a cooldown period of 200ms always follow after a detection (to avoid over detection). 

3. Level 3: Execution of the experimental condition (loop if with white background inside of level 2). 
In case of the choice of Synch or Asynch condition in the graphical interface, the task_code_SYNCH.vi or task_code_ASYNCH is executed. 
- In task_code_SYNCH.vi the steps are: 
	-> Read the condition from the CardioSynchExperimentalMatrix (column 1-4 according session specified in the GUI). 
	-> Test if a R-peak has been detected
	-> If previous test is true: 
		-> If trial is value 1, play the tone and send a trigger 5. 
		-> If trial is value 0, no sound played and send a trigger 6. 
- In task_code_ASYNCH.vi the steps are: 
	-> Read the condition from the CardioSynchExperimentalMatrix (column 1-4 according session specified in the GUI). 
	-> Read time to wait until next sound CardioSynchExperimentalMatrix (column 5 if bloc 1-2 and column 6 if bloc 3-4)
	-> Test if the inter-stimulus is engough
	-> If previous test is true: 
		-> If trial is value is 1, play the tone and send a trigger 7. 
		-> If trial is value 0, no sound played and send a trigger 8.

At the end of the CardioSynchExperimentalMatrix (after 300 stimuly), the task is blocked. It is why it is necessary to restart a file to reinitialise these elements.
